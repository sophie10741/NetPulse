# Ревью кода NetPulse: найденные проблемы и что с ними сделано

Исходная версия — дипломный проект (2025). Перед публикацией код был пересмотрен:
найденные проблемы записаны ниже, исправления покрыты автотестами (`python manage.py test`, 61 тест).
Исходное состояние сохранено в Git: тег `v0.1-diploma`, после исправлений — `v0.2-hardened`.

## Исправлено

| # | Проблема | Серьёзность | Что сделано |
|---|----------|-------------|-------------|
| 1 | Шаблоны команд подставляли значения из формы без проверки; команда выполнялась по SSH от root (внедрение команд) | Критическая | Добавлен `command_builder.py`: каждый параметр проверяется по типу (IP, число в диапазоне, имя пользователя, имя интерфейса и т. д.), пароль экранируется. Тесты на внедрение |
| 2 | Пароль пользователя печатался в консоль при каждом входе (`login_ajax`) | Высокая | Строка удалена, добавлен тест, что пароль не попадает в stdout |
| 3 | Секреты в коде: `SECRET_KEY`, пароль БД, SSH-логин и пароль `root/toor`; `DEBUG=True`, `ALLOWED_HOSTS=['*']` | Высокая | Всё вынесено в переменные окружения (`.env`, в репозитории только `.env.example`) |
| 4 | Запуск сканирования, статус сканирования и JSON топологии были доступны без входа | Высокая | Добавлен `@login_required`, тесты на редирект анонимов |
| 5 | Обращения к `device.ip_address`, хотя IP хранится в интерфейсах: страницы SSH и проверка статуса падали бы с ошибкой | Средняя | Свойство `NetworkDevice.ip_address` (первый интерфейс с адресом) |
| 6 | SSH: путь к ключу зашит в код, принимался любой хост-ключ, поддерживались только RSA-ключи | Средняя | Путь к ключу в настройках; хост-ключи запоминаются при первом подключении (TOFU) и проверяются дальше |
| 7 | Сканер: один глобальный SSH-клиент на все потоки, соединение закрывалось внутри цикла, при ошибке возвращалась строка вместо списка, обращение к `None`, MAC переходил на следующий интерфейс, нет таймаутов | Средняя | Отдельный клиент на каждый узел, закрытие в `finally`, исправлен разбор, таймауты. Тест полного сканирования двух узлов на подменённом SSH |
| 8 | Две конфликтующие ветки миграций (`0002_*`) | Средняя | Миграции пересозданы |
| 9 | В архиве отсутствовал шаблон `access_denied.html` (страница входа) | Средняя | Восстановлен по приложению к ПЗ |
| 10 | Дубли маршрутов в `urls.py` (`admin`, главная, `logout`), `favicon` в старом regex-формате, конфликт имён `login`/`logout` с `accounts/` | Низкая | `urls.py` переписан, имена маршрутов сохранены |
| 11 | `tests.py` не был набором тестов, `test_ssh.py` — ручной скрипт с IP лаборатории | Низкая | Заменены автотестами |
| 12 | В моделях `Connection`, `Category`, `Utility` метод назван `str` вместо `__str__` | Низкая | Исправлено |
| 13 | JSON топологии вставлялся в страницу как есть (фильтр `safe`); имя хоста приходит с устройства, поэтому имя вида `</script>...` позволяло выполнить скрипт в браузере администратора (XSS) | Высокая | Данные передаются через `json_script`, добавлен тест |
| 14 | Фильтр устройств, не нашедший совпадений, показывал стартовую страницу «сеть не отсканирована»; схема строилась по отфильтрованным устройствам, а связи брались все, что ломало отрисовку | Средняя | Схема всегда строится по всем устройствам, фильтр действует только на таблицу |
| 15 | В таблице устройств у всех стоял статус «Online» (проверка была закомментирована) | Низкая | Статус берётся из данных устройства |
| 16 | Ключевые слова типов устройств не очищались от пробелов и пустых элементов: пустой элемент делал любое устройство «сервером» | Средняя | Разбор вынесен в `parse_keywords`, проверка IP-адреса и непустых слов, сообщения об ошибках |
| 17 | Страницы SSH-команды и выбора интерфейса не были связаны с интерфейсом, а ссылки «назад» вели на несуществующие адреса | Низкая | Добавлены действия в таблицу и меню схемы, исправлены ссылки, значения формы сохраняются (кроме пароля) |
| 18 | Удаление заметки выполнялось по GET-запросу: достаточно было заставить администратора открыть ссылку или картинку на чужой странице (CSRF) | Средняя | Удаление только POST с подтверждением и CSRF-токеном, кнопки правки и удаления видны только автору |
| 19 | Несуществующая «полезность» вызывала ошибку 500 вместо 404 | Низкая | `get_object_or_404` |
| 20 | Калькуляторы: сообщение об ошибке ввода не показывалось (шаблон выводил пустые поля результата); деление на ноль при нулевой мощности сервера приводило к ошибке 500; для сетей /31 и /32 число хостов считалось неверно | Низкая | Ошибки выводятся, деление на ноль обрабатывается, для /31 и /32 расчёт исправлен |
| 21 | Пагинация «Полезностей» теряла выбранную категорию; в тёмной теме карточки заметок и полезностей оставались белыми с нечитаемым светлым текстом | Низкая | Категория сохраняется в ссылках, цвета берутся из переменных темы |

## Известные ограничения (в бэклоге)

| # | Ограничение | Комментарий |
|---|-------------|-------------|
| A | Любой вошедший пользователь может выполнять произвольные команды по SSH (`ssh_command_view`) | Для инструмента администратора это ожидаемо, но нужна ролевая модель: кто и какие команды может запускать |
| B | Шаблон `sudo_no_auth` даёт пользователю sudo без пароля | Допустим только в лабораторной среде; в документации помечен как lab-only |
| C | Ошибки сканирования пользователю не показываются: при недоступном узле интерфейс просто возвращает на стартовую страницу | Нужны статус и сообщение об ошибке на странице прогресса |
| D | Сканирование идёт в потоке `threading.Thread` с глобальным флагом; нет очереди и повторного запуска | Кандидат на очередь задач (Celery + RabbitMQ), также снимет блокировки SQLite |
| E | Обнаружение через `arp -an` видит только соседей по L2 и требует `net-tools` на узлах | Ограничение метода, описывается в архитектуре |
| G | Выбранный на странице выбора интерфейс не передаётся в форму шаблона | Пользователь вводит имя интерфейса вручную |
| H | Колонка SNMP в списке устройств пустая: метод остался на модели интерфейса | Решить: вернуть SNMP или убрать колонку |
| I | Мёртвый код: `scan.html`, view `calculator`, `SomeView`, папка `templates/uncomplite`, `notes/comment_form.html`, `monitor/urls.py` | Удалить при следующей чистке |
