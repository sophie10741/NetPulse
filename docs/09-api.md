# NetPulse: описание API

Версия 0.1, октябрь 2026.

## 1. Текущий HTTP API

Приложение отдаёт HTML-страницы и несколько JSON-интерфейсов. Спецификация OpenAPI 3.0: [api/openapi.yaml](api/openapi.yaml).
Коллекция Postman для ручной проверки: [api/NetPulse.postman_collection.json](api/NetPulse.postman_collection.json).

| Метод и путь | Назначение | Доступ | Ответ |
|--------------|------------|--------|-------|
| POST `/login/` | Вход | Все | JSON `{success, error?}` |
| POST `/validate_user/` | Проверка выданных учётных данных | Все | JSON `{success, error?}` |
| POST `/complete_registration/` | Завершение регистрации | Сессия после `/validate_user/` | JSON `{success, error?}` |
| GET `/logout/` | Выход | Все | Перенаправление |
| GET `/api/network_topology/` | Устройства и связи для схемы | Вошедший пользователь | JSON `{nodes, edges}` |
| POST `/scan/start/` | Запуск сканирования | Вошедший пользователь | Перенаправление |
| GET `/scan/status/` | Идёт ли сканирование | Вошедший пользователь | JSON `{scan_in_progress}` |

Особенности текущего интерфейса:

- Аутентификация сессионная (cookie), подходит для браузера, но неудобна для скриптов и интеграций.
- Изменяющие запросы защищены CSRF-токеном: нужны cookie `csrftoken` и заголовок `X-CSRFToken`.
- Ответы об ошибках неоднородны: JSON для входа, перенаправление с сообщением для сканирования.
- Нет ограничения числа попыток входа (`/login/`, `/validate_user/`).

### Как посмотреть спецификацию

Вариант 1: открыть [editor.swagger.io](https://editor.swagger.io/) и вставить содержимое `openapi.yaml`.
Вариант 2: локально через Docker, из корня репозитория:

```bash
docker run --rm -p 8081:8080 -e SWAGGER_JSON=/spec/openapi.yaml -v "$PWD/docs/api:/spec" swaggerapi/swagger-ui
```

После запуска страница доступна по адресу `http://localhost:8081`.

### Как проверить в Postman

1. Импортировать `NetPulse.postman_collection.json`.
2. В переменных коллекции задать `baseUrl` (например, `http://192.168.52.129:8000`), `username` и `password`.
3. Выполнить по порядку: «Получить CSRF-cookie», «Вход», затем остальные запросы. Тесты в запросах проверяют коды и формат ответов.

## 2. Проект REST API версии 1 (не реализовано)

Цель: дать скриптам и интеграциям доступ к тем же возможностям, что и интерфейс, и сделать API единым источником логики для интерфейса и внешних клиентов.
Предлагаемая реализация: Django REST Framework, токены, спецификация OpenAPI генерируется из кода.

### Принципы

| Принцип | Решение |
|---------|---------|
| Аутентификация | Токен: `POST /api/v1/auth/token/` с логином и паролем, далее заголовок `Authorization: Token <значение>` |
| Формат | JSON, UTF-8, даты в ISO 8601 |
| Ошибки | `{"error": {"code": "...", "message": "...", "fields": {...}}}` и корректные коды HTTP |
| Списки | Постраничный вывод `?page=`, фильтры через параметры запроса |
| Доступ | Роли из документа «Роли и пользовательские истории»; опасные операции только для разрешённых ролей |

### Ресурсы

| Метод и путь | Назначение | Требование |
|--------------|------------|------------|
| POST `/api/v1/auth/token/` | Получить токен | FR-01 |
| GET `/api/v1/devices/` | Список устройств, фильтры `name`, `device_type`, `status` | FR-18 |
| GET `/api/v1/devices/{id}/` | Устройство с интерфейсами | FR-18 |
| GET `/api/v1/topology/` | Узлы и связи | FR-17 |
| POST `/api/v1/scans/` | Запустить сканирование: `start_ip`, словари ключевых слов. Ответ 202, идентификатор | FR-10 |
| GET `/api/v1/scans/{id}/` | Состояние: `running`, `finished`, `failed`; найдено устройств; список ошибок по узлам | FR-15 |
| GET `/api/v1/templates/` | Каталог шаблонов: ключ, описание, параметры, подсказки, пояснение команды | FR-30 |
| POST `/api/v1/devices/{id}/commands/` | Тело: `template`, `parameters`, `dry_run`. При `dry_run=true` возвращает итоговую команду и пояснение без выполнения; иначе выполняет и возвращает результат | FR-31, FR-33, FR-36 |
| GET `/api/v1/audit/` | Журнал выполненных действий | FR-35 |

### Примеры

Предпросмотр команды (то, чего нет в текущем интерфейсе, FR-36):

```http
POST /api/v1/devices/3/commands/
Authorization: Token 9d1c...
Content-Type: application/json

{"template": "change_ip", "parameters": {"ip": "10.0.0.5", "mask": "24", "interface": "eth0", "old_ip": "10.0.0.4"}, "dry_run": true}
```

```json
{
  "command": "ip addr add 10.0.0.5/24 dev eth0 && ip addr del 10.0.0.4/24 dev eth0",
  "description": "Добавляет новый адрес на интерфейс и удаляет старый",
  "executed": false
}
```

Ошибка проверки параметров:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Параметры не прошли проверку",
    "fields": {"ip": "ожидается IP-адрес"}
  }
}
```

### Порядок реализации

1. Журнал действий (FR-35) и сообщения об ошибках сканирования (FR-15): сервисный слой, который будет использовать и интерфейс, и API.
2. Предпросмотр и подтверждение команды (FR-36).
3. Токены и ресурсы `devices`, `topology`, `scans`, `templates`, `commands`.
4. Генерация OpenAPI из кода и обновление коллекции Postman.
